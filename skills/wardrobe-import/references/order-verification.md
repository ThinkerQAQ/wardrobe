# 订单核验与证据

- 对每个成交行优先使用稳定来源键 `platform:order_id:line_id`；同订单不同 SKU 使用不同 line_id。真实订单号不应臆造。如果仅有订单搜索页，先尝试进订单详情底部「订单信息」获取号码；取不到但用户明确确认拥有时，可用「平台+真实日期+店铺+商品规格+金额」生成确定性临时来源键，标记订单号待核实，并用受控本地 SQLite 事务与备份（现有 MCP 新增接口不支持缺失订单号），不能假称获得真实订单号。
- **不能把退款当退货**：`交易成功、部分退款成功` 属于整个订单的状态，不能据此排除所有商品；单件「退款成功，金额 ¥0.00」实际退回金额为零，也不表示退货。其他正数退款可能是价保/补差/部分退费或退货退款，需分别核对售后类型、金额和物流，用户本人明确确认仍有该件时优先保留这条持有事实。未确认实退金额不要擅自扣减；订单总额与商品金额分别保留。
- 分别核实购买规格、当前是否持有、实际合身与用户本人评分；后三项默认待确认/未评价。
- 同一商品的更多主图不应创建新的商品记录；图片只在归档成功后更新记录路径。
- 身体净尺寸、合身成衣尺寸分别由 `get_wardrobe_body` 获取，不凭通用 M/L 尺码猜测合身。
