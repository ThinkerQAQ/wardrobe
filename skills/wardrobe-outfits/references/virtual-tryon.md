# AI 真人试穿：输入要求与验收清单

本文件约束基于用户本人照片的虚拟试穿。生成图只能称为「AI 近似预览」，不能冒充本人真实实穿照。**缺少可确认、真正进入生成工具的本人正脸参考图时，不得生成并声称是本人。**

## A. 生成前准备（不满足就暂停本人试穿）

1. `identity_photo`：用户确认的本人正面清晰真人实拍；**发型库图的模特五官绝不能当成本人**。避免被手机遮住、过暗、过远或侧脸的照片。
2. `body_photo`：真人实拍半身或全身；身高和体重只能约束大致比例，不能独立推断五官和准确体型。
3. `hairstyle`：本次用户指定的 HAIR 记录，只参考头发长度、侧面、顶部造型。不能引用示意图的人脸。
4. `outfit_items`：最终确定的衣服/鞋子的 Wardrobe 商品 ID，逐件核对商品图、颜色、规格、版型和持有状态。
5. `accessory_allowlist`：用户明确指定并在当前搭配中存在的配饰 ID；**默认空数组**。从参考实拍/商家模特图中看到的包、手表、咖啡杯或配饰，不因此变成允许的搭配。
6. `image_input_verified`：**确定真人照片、实际商品图真正作为图像输入传进了所选生成器**。仅通过 MCP 在会话里看到，不等于生成器已经接收到文件。不能确认时不能进行本人试穿生成。

## B. 单品白名单与禁止配件（硬约束）

**只允许明确选择的商品**（例如在本次会话中核对的 `selected_outer_id`、`selected_inner_id`、`selected_pants_id`、`selected_shoes_id`）。真实商品编号和颜色仅从用户自己的 SQLite 实时读取；开源 Skill 不写入任何人的真实购买记录。不得添加其他衣服或未选配饰。

默认禁止：**手提包、托特包、公文包、背包、单肩包、手表、手机、咖啡杯、雨伞、帽子、围巾、手套、项链、领带、装饰腰带、任何未授权配件**。包包在用户没有指定时绝不出现；不得从商家模特图、真人参考图或先前生成的失败预览图复制包包。

眼镜按用户本人真实照片与明确要求保留；不能仅从发型模板或商家图推断有眼镜。双手自然下垂、两手**空着**；不拿包、杯子、手机，不插袋遮挡衣服。

## C. 摄影构图与人脸（硬约束）

**人物图生成阶段仅一张、单人、纯照片**，默认竖幅 3:4 或 2:3。正面平视，人物**直立正对镜头**：头、眼睛、肩膀、胸口、腿脚全部朝前，双眼自然直视镜头，五官正面可见；保持用户本人面部特征。

**禁止侧脸、三分之二侧脸、回头、低头、背面、侧面、坐姿、行走分镜、视线偏向画外**。正面不是“画面里存在一张侧面脸”——必须确实直视镜头。

头顶到双鞋鞋底完整入画，不裁头、不裁脚、不虚构长腿。单背景、自然比例、柔和光线、手部姿势正常。**人物图生成阶段**禁止多宫格、拼贴、四视图、侧栏商品信息、说明文字、数据面板、标签、海报、AI 产品广告。**最终展示阶段例外**：用户选定 `lookbook_card_v1` 时，由本机 Go 服务（Web `/api/lookbook/render` 与 MCP `compose_wardrobe_lookbook` 共用）的确定性模板（不是生成模型）在右侧绘制已核验的商品和发型信息，左侧仍是一张完整人物图。

## D. 生成文案模板

**正向描述**（使用真实素材，并在送进生成器前逐项确认）：

> 基于已经传入的用户本人正面真人实拍及真实体型参考，对同一个人进行写实虚拟试衣编辑。保持本人相貌与五官，不使用发型示意图的脸。人物正面站立，整个躯干与面部正对摄影机，双眼直视镜头，双臂垂放，双手完全空着。仅此一人、此一套衣服、此一幅 3:4 竖版照片，从头顶到两只鞋底完整入镜。服装严格遵从已核验的商品 ID、颜色、长度、版型。发型只依据 HAIR 样式；背景简洁。

**负向硬约束**：

> NO bag, tote, briefcase, backpack, handbag, shoulder bag, watch, phone, coffee cup, umbrella, scarf, hat, jewelry, tie, belt or accessory not explicitly whitelisted. NO side face, profile, three-quarter face, turned head, looking away, back view, seated pose, walking pose, hands in pockets, cropped feet or cropped head. NO collage, grid, moodboard, magazine layout, labels, wardrobe item panel, price panel, text, watermark, multiple people, changed facial identity or hair model's face. ONE person, ONE direct front-facing standing pose, ONE full-length photograph.

若用户指定了白名单配饰，排除项中对应类别可按其请求解除；不能默认增加。

## E. 生成结果验收（全部通过才可交付）

| 检查 | 通过条件 | 失败样例 |
| --- | --- | --- |
| Q1 构图（人物图阶段） | 人物生成阶段一张独立照片、恰好一人、没有小图拼接；最终 `lookbook_card_v1` 右侧由程序绘制的商品信息除外 | AI 生成的多宫格、人物侧面分镜、凭空画出的商品清单 |
| Q2 面容 | **正脸对镜头**、双眼可见、与本人真人参考尽量一致 | 侧脸、背脸、别人五官、脸被挡住 |
| Q3 全身 | 头顶和**双鞋底**完整、站姿正面 | 半身照、裁脚、坐姿、走路 |
| Q4 配饰 | 没有未授权的包包、手表、手机、杯子等 | 手里拿包或杯子、无根据加手表 |
| Q5 服装 | 每件服装与指定商品图一致，不换款、不改色 | 白色裤子改色、风衣变其他款 |
| Q6 发型 | 与用户本次指定发型一致、**不复制发型图库人脸** | 侧分/短背头错误、复制陌生面孔 |
| Q7 真实度 | 身材比例自然、本人脸可辨认 | 不真实身高、明显变脸、错误体型 |

Q1～Q6 任意失败即为**无效预览**；Q7 无法可靠判断时也不能宣称真人试穿成功。先修正参考输入与编辑任务，再考虑重新生成；如果模型重复违背硬约束，应停止使用该生成器并说明限制，不要无限随机重试。**不得把失败图或 AI 生成图保存进 Wardrobe 的真人实穿证据。**

## F. 传输和软件限制

SQLite 与照片主存储在本机，但用户通过云端图像生成器进行试穿时，提交的本人照片和商品参考图会发送到对应服务。仅提交用户明确授权的必要参考图，不上传原始订单与全量个人数据库。

Wardrobe MCP 提供图像读取，不提供能保证本人五官百分百锁定的试穿渲染器。Skill 是行为要求，不是第三方模型的硬保证。
## 固定的 Lookbook 最终版式（与 AI 人物生成分开）

用户当前选择的最终展示版式为 `lookbook_card_v1`，尺寸 **1200 × 1800 PNG**。**禁止要求 AI 把人物、商品图、编号、文字和侧栏一次性画出来**，因为模型会臆造商品图、错字、多余配饰或改变面容。

固定流程：

1. 先经真实照片 + 身材 + 产品图检查，得到**仅人物的竖幅穿搭预览**；不得产生带商品条、数字面板或文字的 AI 海报。
2. 在 `/lookbook.html` 选择左侧人物图（通过本机回环 API 发送给 Wardrobe Go 进程，**不上传第三方**）。可以在排版阶段用已保存的 Look 照片检查模板，但不能将其视为新的 AI 试穿。
3. 从本机 SQLite 的已有 Look 或经过确认的商品 ID 选择外套、衬衫中层、裤子、鞋子和 HAIR 发型，右侧面板由 **本地 Go 共用渲染器确定性绘制**。商品名、款式、颜色、尺码不得由生成模型自编。
4. 浏览器或 MCP 生成 `lookbook_card_v1`：**左侧单张全身人物图，右侧 4 张商品卡 + 发型参考 + 穿搭说明**，然后本地下载 PNG。缺少商品主图必须报错，不能由模型补图。
5. **分别验收**：（A）人物图是否本人正脸、衣服准确、站姿自然；（B）右侧商品图片与 SQLite 是否一致；（C）最终合成版式/信息是否正确。模板的 Q1 检查要求只针对 **AI 人物生成阶段**，不是禁止程序固定合成的商品信息面板。

图像通过 MCP 发往云端助手时，人物图本身会进入该 AI 服务；通过本机 Web UI 生成则不发第三方。**不要把云端 MCP 渲染误称为完全离线。**\n\n这个固定模板**能保证栏目布局、信息来源和像素尺寸**，不能保证左侧 AI 人像相似度或服装换装的真实度。不要把 `lookbook_card_v1` 宣称为完全自动受控的真人试穿渲染器；当前 Wardrobe 的 `/api/tryon/render` 仍会因未配置受控渲染器而拒绝。
