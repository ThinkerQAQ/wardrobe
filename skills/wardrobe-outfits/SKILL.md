# 搭配

1. 通过 `get_wardrobe_workflow(name="wardrobe-aesthetics")` 或 `get_wardrobe_rules` 获取用户授权的审美依据，再用 `search_wardrobe` 和必要时的 `get_wardrobe_body` 查询衣橱与身体资料。先确认用户实际持有及合身状态；未经确认的历史尺寸只能作参考，不能当成当前测量值。云端 AI 调用这些工具时会收到返回的数据，避免读取不必要的私人字段。
2. `list_wardrobe_hairstyles` 获取用户本机保留的发型参考（HAIR 编号）；发型是外观搭配，**不是**购买商品。通过 `get_wardrobe_image(kind="hairstyles")` 阅读参考图。
3. 服装层次：`inner` 贴身 T恤/长袖；`mid` 衬衫/毛衣/卫衣；`outer` 外套；`pants` 裤装；`socks` 袜；`shoes` 鞋。类型可空缺；不要强行补全。
4. 配饰分开：`glasses`、`hat`、`gloves`、`necklace`、`watch`、`belt`、`scarf`、`bag`、`tie`，兼容历史 `accessory1`/`accessory2`/`other`；发型用 `hair` 引用 HAIR 记录，其他槽位只能引用现有商品编号。
5. 用户明确要保存时先读取搭配 `version`，用 `save_wardrobe_look` 存储；用户评分才使用 `rating`。不将旧表默认三星当作本人偏好。
6. 提建议可以给备选和理由，但未经授权不写入，不能假定用户当前仍拥有历史商品。

## AI 真人试穿：严格约束和失败处理

详见 [真人试穿验收规范](references/virtual-tryon.md)。通过 MCP 读取该 Skill 时，服务端必须同时返回此参考规范。每次试穿前逐项执行，**不能只引用上一轮已失败的图片继续猜测**。

1. **以用户真人照片锁定身份**：使用用户确认真实的正脸照和尽可能清楚的全身体态照。**先调用 `preflight_wardrobe_tryon`**（或本地 `POST /api/tryon/preflight`）检查真人参考、商品图和配饰白名单；`ready=false` 时不能发起本人试穿。预检查通过仍须确认这些图片真实进入受控生成器；通过 MCP 看到 Look 照片不代表生成器已经收到。当前服务端渲染接口会拒绝执行，因为尚未接入受控生成和结果验收。身高体重只是比例证据，不能凭数值生成本人五官。发型库 AI 模特的脸**一律不是用户本人**，只能参考头发样式。
2. **衣橱商品严格白名单**：生成的衣服和鞋只来自本套搭配明确选择并核验的 Wardrobe 商品 ID；其他所有服饰或配件，**除非用户明确指定，否则不允许出现**。尤其严禁凭空添加**手提包、托特包、公文包、背包、单肩包、手表、手机、咖啡杯、帽子、围巾、腰带等**。商品广告或真人参考照里有包、表、杯子，也不代表用户本次选了它。双手自然下垂、空手。
3. **必须正脸、正面、站立、完整全身**：单人正对镜头，头与身体朝向镜头，双眼看向镜头，五官正面可见，头顶和两只鞋底完整入镜。**侧脸、斜脸（三分之二侧脸）、低头、回头、背面、坐姿、走路都不合格。**
4. **区分人物生成和最终搭配卡两个阶段**：人物生成阶段只产生单张正面全身写实照片，不允许模型生成商品说明、图片拼贴或文字。用户已经选择 `lookbook_card_v1` 作为默认**最终展示版式**：生成后由 Wardrobe Go 服务通过 `/api/lookbook/render` 和 MCP `compose_wardrobe_lookbook` 共用同一个固定合成器生成**左侧人物全身图 + 右侧真实商品图、编号、发型和要点**。双栏搭配卡是允许的，**但右侧不能交给图像模型画**。生成 1200×1800 PNG；人物脸仍需单独核验。
5. **固定版式 MCP 接入**：调用 `get_wardrobe_capabilities` 检查支持范围，传已保存 Look ID 以及一张独立人物图（`portraitImageBase64`）或既有 Look 归档原照（`portraitLookId`）给 `compose_wardrobe_lookbook`。后端以 SQLite 中的原始商品照片、编号和尺码绘制右侧，左侧只保留一张人物图；预览不等于本人真实试穿。用户在 Web UI `/lookbook.html` 调用的也是同一 Go 合成器，人物图只传到本机回环服务。\n6. **生成前核对输入**：真人正脸、真人身材、指定发型、每件商品、配饰白名单、输出构图，逐项确认是否可用。不能证明生成工具能接收真人参考时，不生成冒充本人面容的效果图。可以提供已明确标注的匿名搭配示意，但**不能当作本人试穿**。
7. **生成后逐项硬验收**：正脸对镜头、本人脸部相似度、发型、全部选中服饰、无未授权包和配件、单幅照片、全身入镜。**任一不合格即判定失败**，不保存到真人实穿图库，不说成功。更换有效参考或使用定向修图；连续失败必须说明图像工具的限制，不要无限随机重试或承诺文字 Skill 能保证人脸还原。
