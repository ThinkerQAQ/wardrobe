# Wardrobe 真人试穿：固定执行流程与失败保护

这个功能与 `skills/wardrobe-outfits/SKILL.md` 互相补充：

- **Skill** 是对 AI 的操作说明，文字不是程序级硬约束。
- **Go 服务端**是检查者：只要预检查失败，就无法通过 Wardrobe 的渲染入口继续。
- **渲染适配器和图像结果验收器尚未实现**：因此当前 `POST /api/tryon/render` 固定返回 HTTP 501。当前阶段不会因为“参考资料看起来完整”就向第三方发送照片或伪称试穿成功。
- **独立调用 ChatGPT 生图工具不受 Wardrobe 控制**。要保证不绕过验证，未来需将生成请求统一交给 Wardrobe 管理，而非让 AI 随意调用外部图像生成器。

## 可执行状态机

```text
选择衣橱搭配和参考 Look
           |
本地确认真人正脸、真人全身照片（分别点击确认）
           |
归档图片 SHA-256，绑定到用户声明
           |
POST /api/tryon/preflight
           |
      ┌────┴────────┐
      ▼             ▼
  blocked    ready_for_renderer_only
      |             |
  返回缺失原因       未来：受控渲染适配器（尚未接入）
                    |
               真实图片字节进入模型（必须核对输入）
                    |
               模型生成候选图
                    |
               图像结构检查 + 本人最终验收（尚未实现）
                    |
               accepted / rejected（尚未实现）
```

**注意**：`ready_for_renderer_only` 仅说明本地用户提供的证据通过了结构核验，不代表自动识别出真人脸，更不代表模型已收到图片或输出通过质量检查。

## 当前可操作的 Web UI

进入 **搭配** 页面：

1. 找一张本人真实正脸的照片，先查看原图，再点击 **确认本人正脸**。发型示意、AI 图片、侧脸不能确认。
2. 找一张本人的真实全身照片，再点击 **确认本人全身**。同一张照片符合两者要求时可分别确认。
3. 在待试穿搭配上点击 **试穿前检查**，选择已确认照片对应的 Look ID。
4. 程序会检查实际商品 ID、商品 JPEG 是否存在、是否有明确选择的配饰、真人参考照片文件及确认记录。每个失败都返回具体原因。
5. 即使本地预检查通过，在没有受控生图器和最终图像审核之前，**仍然不能通过这个入口生成或保存真人试穿图**。

用户确认并不等于自动人脸核验；系统记录的只是用户声明和照片摘要，用户替换照片后立即作废。

## JSON API

本地服务默认只监听 `127.0.0.1`，不要公开暴露：

- `POST /api/tryon/confirm-photo`：`{"lookId":"LOOK-DEMO","role":"face","confirmRealPhoto":true,"confirmFrontal":true}`，全身角色使用 `role="body"` 和 `confirmFullBody=true`。
- `POST /api/tryon/preflight`：`{"lookId":"LOOK-OUTFIT","faceLookId":"LOOK-FACE","bodyLookId":"LOOK-FULLBODY"}`，返回 `ready`、`blocks`、衣服/配饰白名单和固定姿势。
- `POST /api/tryon/render`：**当前 HTTP 501**，没有可核实图像输入和输出验收器，不允许跳过。
- MCP `preflight_wardrobe_tryon`：只读返回本地预检查结果。该工具不会自行上传照片或生成图像。\n- MCP `get_wardrobe_tryon_evidence`、`confirm_wardrobe_tryon_photo`：查询或在用户明确授权后记录真实照片角色声明，绑定原图 SHA-256；不执行人脸识别。\n- MCP `compose_wardrobe_lookbook`：仅将外部已经提供的单张人物图和本地商品原图合成为 PNG，**不是** `/api/tryon/render`，不会自动生成或验证本人脸。

示例均为虚构编号。正式使用应在本机读取真实 Wardrobe 记录，不在 GitHub 记录用户照片或真实商品清单。

## 目前可以真正保证什么

| 层次 | 已有的程序级检查 | 不能保证什么 |
| --- | --- | --- |
| 真人照片来源 | 用户在本机明确声明，照片文件符合基本尺寸与格式，SHA-256 防替换 | 声明的人一定是本人；照片一定正脸（仍需人工确认） |
| 商品来源 | 所选商品确实存在 SQLite，图片文件存在并且可解析 | 商家主图与真实衣服颜色、版型 100% 一致 |
| 配饰 | 仅列出搭配 slots 里明确选择的配饰，没有包则白名单没有包 | 外部模型不会凭空画包，未来需视觉验收 |
| 人物站姿 | 固定正面、正头、双脚自然并列、双手空着的渲染计划 | 外部模型绝不歪头、伸腿 |
| 外部生成 | 当前无受控渲染器时拒绝调用 | 其他独立工具可以绕过 Wardrobe |
| 输出验收 | 输出不会被当前入口自动当作本人实穿保存 | 尚无自动构图/面部一致性判定器 |

要完成下一阶段，需要接入**真正接收参考图片字节**的渲染器，并在服务器实现输出审核（脸、头部角度、脚部、额外配饰、具体 SKU）和失败重试；用户最后仍应进行本人确认。
