# Wardrobe 固定搭配卡：`lookbook_card_v1`

用户确认以“双栏穿搭卡”为目前默认可接受的**展示格式**。区别于此前只有一张纯照片的试验：这一版右侧允许商品、发型、说明文字，但**这些元素由本机程序绘制，不能让 AI 生成**。

## 输入 → 确定性输出

```text
A. 真人试穿检查（Go，已有；未经真人身份确认不得声称真实试穿）
     │
B. AI 或人工提供一张独立的全身人物图（图像编辑，目前由外部工具完成）
     │
C. Wardrobe 本地 Look / SKU / HAIR 数据（SQLite）
     │
D. Go 共用图像合成器（Web 本地 API + MCP 统一版式、商品图、文字）
     │
E. 1200×1800 PNG → 人工检查脸/衣服/排版 → 交付或标记失败
```

A 和 B 目前**尚未集成成不可绕过的单条渲染流水线**；因此不能宣称已经解决本人脸部一致性或达到自动真人试穿的生产级保障。真正强约束是 **D → E 的固定排版和商品字段**。

## 如何使用

打开本地 Wardrobe Web UI，进入「搭配」并点击 **生成搭配效果卡**，或访问 `http://127.0.0.1:17936/lookbook.html`（端口以实际监听为准）。

1. 选择已保存 Look，或从下拉框分别选择外套、中层衬衫、裤装、鞋子及发型。每件商品只能引用 SQLite 中的真实 ID。
2. 选择左侧人物图：可以是 AI 编辑生成的单人正面全身照片（建议），也可以从拥有归档照片的 Look 自动读取原照，仅用于检查版式。
3. 点击「生成固定版式预览」，右侧即由程序读取各商品本地图片与名称、颜色、尺码并固定排版。
4. 点击「下载 PNG」，得到 1200×1800 的完整穿搭卡。

图片在本机 Go 服务中合成；浏览器将所选人物图通过 `localhost` 发送给 Wardrobe 的 `/api/lookbook/render`，不会上传到 Adobe、Runway 或 GitHub。经云端 MCP 调用时，人物图会进入对应 AI 服务。MCP `compose_wardrobe_lookbook` 与本地 Web UI 使用同一份 Go 合成器。

## 保证边界

| 可以通过代码保证 | 目前不能保证 |
|---|---|
| 最终卡片两栏比例、面板位置、卡片顺序、输出尺寸固定 | 外部 AI 人物图的面容与本人完全一致 |
| 商品名称、SKU、颜色、尺码直接来自 SQLite，而非 AI 编造 | 外部生成的人物真正穿的是所选实物 |
| 发型仅作为右侧参考图片，不参与人脸身份替换 | 生成器自动去掉源图中的包、手表 |
| 某件商品无本地图片时直接报错，不用 AI 凭空补图 | 任意第三方 AI 图像服务都遵守正脸与站姿 |

当前支持四个主要服装槽位（外套、中层/内搭、裤装、鞋履）。其它配饰/衣层并未进入本模板，不能默认为已选择；需要增加新槽位时应先调整 Go 模板和测试。

## 回归测试

- `go test ./...` 检查 Web 资源被 Go embed 收录、试穿预检查默认版式说明正确。
- `node --check web/lookbook.js` 检查前端语法。
- 在真实本机 Web UI 中用已有穿搭与本地归档人物图生成并下载 PNG，检查是否 1200×1800、是否双栏且 4 款商品数据正确。
- 最后人工检查左侧 AI 真人预览的身份和服装质量；不能把排版测试通过等同于真人试穿通过。

## MCP 直接出图

使用 `compose_wardrobe_lookbook` 输入已保存 `lookId` 和 `portraitLookId`（有本地归档照的 Look）或 `portraitImageBase64`（用户同意的独立人物 JPEG/PNG）。工具返回一张 `image/png`，**不默认归档**；商品图和中文字段均由本地 SQLite 加载。具体权限见 [MCP 清单](MCP.zh-CN.md)。
